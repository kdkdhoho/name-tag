# 바른매칭 경쟁 리서치

조사일 2026-09-04. 목적은 해커톤 발표에서 "이름표"와의 차별점 방어.
표기 규칙: **확인**은 1차 출처에서 직접 본 것, **추정**은 근거를 적은 추론, **미확인**은 공개 자료에서 못 찾은 것.

## 1. 요약 (5줄)

1. 바른매칭은 법인이 아니라 개인사업자(대표 최용운, 인천 중구)가 운영하는 앱이고, 앱스토어 출시는 2025년 5월이 아니라 **2026-04-18**이다. 규모는 Google Play 다운로드 500+, App Store 한국 평가 2건(평점 5.0), 텍스트 리뷰 0건이다. (확인)
2. 개 쪽 성향 10종의 정확한 항목을 운영 코드에서 확인했다. 신체운동·두뇌자극·실내차분·분리불안·경계짖음·요구짖음·낯선사람·어린이·다른개·소동물이며 각 0~10점을 **보호소 담당자가 직접 슬라이더로 입력**한다. AI 추정이 아니다. (확인)
3. 사람 쪽은 "10가지 문항"으로 **원하는 성향의 희망 수치**를 받아 개의 성향 수치와 비교하는 구조다. 주거 유형·크기 제한·임대인 동의·집 비는 시간 같은 제약 조건을 묻는다는 근거는 공개 자료 어디에도 없다. (희망 수치 비교는 확인, 제약 조건 미질문은 미확인)
4. 매칭 결과는 1위부터 5위까지 "N% 찰떡" 랭킹 카드이고, 왜 그 점수인지 설명하는 문장은 결과 목록에 없다. 입양 후 체크리스트나 교육 기능도 없다. 그 자리를 198,000원 스타터 키트 판매가 대신한다. (확인)
5. 사업의 법적 실체는 매칭 플랫폼이 아니라 통신판매업이다. 자사 푸터에 "동물을 직접 판매하거나 소유권을 이전하지 않으며, 입양 계약의 법적 책임은 보호소와 입양 당사자에게 있습니다"라고 명시돼 있다. (확인)

## 3. 입력 항목과 매칭 방식

### 3-1. 개 쪽 성향 10종 (확인, 운영 코드에서 직접 확보)

barunmatch.com의 사설보호소 상세 모달(`/43`)과 아이 등록 폼(`/375188206`)의 자바스크립트에 10개 키가 그대로 하드코딩돼 있다.

```
const keys = ["신체운동","두뇌자극","실내차분","분리불안",
              "경계짖음","요구짖음",
              "낯선사람","어린이","다른개","소동물"];
```

화면에서는 3개 그룹으로 묶여 각각 **0~10점 막대**로 표시된다.

| 그룹 | 지표 | 화면 라벨 |
|---|---|---|
| 🏃 에너지 및 활동성 | 신체운동 | 신체 운동량 |
| | 두뇌자극 | 두뇌 자극 |
| | 실내차분 | 실내 차분함 |
| | 분리불안 | 분리 불안 |
| 🗣️ 환경 및 짖음 | 경계짖음 | 경계 짖음 |
| | 요구짖음 | 요구 짖음 |
| 🤝 사회성 및 친화력 | 낯선사람 | 낯선 사람 |
| | 어린이 | 어린이 |
| | 다른개 | 다른 개 |
| | 소동물 | 소동물 |

값이 없으면 **기본 5점**으로 렌더링된다 (`let score = dog[item.key] !== undefined ? Number(dog[item.key]) : 5;`). 즉 성향을 입력하지 않은 개도 매칭 대상에 들어가며 "보통(5점)"으로 취급된다. (확인)

출처: https://www.barunmatch.com/43 페이지 소스, https://www.barunmatch.com/375188206 페이지 소스

### 3-2. 개 등록 시 보호소가 넣는 전체 항목 (확인)

사진(필수), 이름, 성별(여아/남아), 중성화(완료/미완료), 크기(소형/중형/대형), 나이, 체중, 보호소명, 그리고 성향 10종 슬라이더. 상세 모달에서 추가로 노출되는 필드: 건강상태, 백신여부, 배변습관, 한줄소개, 상세설명 또는 구조사연, 품종, 보호 위치.

등록 권한은 `user.type === 'master' || 'shelter'`로 제한된다. 즉 **성향 데이터의 입력 주체는 보호소 담당자 또는 운영자 본인**이다. 봉사자 입력이나 AI 추정 경로는 코드에 없다. (확인)

### 3-3. 입양 희망자 쪽 입력 (핵심 쟁점)

공식 문구는 아래 셋이 전부다.

| 문구 | 출처 | 표기 |
|---|---|---|
| "10가지 문항 기반 맞춤형 성향 분석 시스템 / 에너지, 짖음, 친화력 등 세밀한 성향 확인 / **나의 희망 수치와 아이의 성향을 한눈에 비교**" | https://www.barunmatch.com/45 | 확인 |
| "활동량, 짖음, 친화력 등 10가지 성향 데이터를 바탕으로 나의 생활 패턴과 가장 잘 맞는 운명의 짝꿍을 찾아보세요" | App Store 설명 | 확인 |
| "신체 운동량, 분리불안, 짖음, 친화력 등 10가지 성향 지표를 분석합니다. **나의 거주 환경과 생활 패턴**에 가장 잘 맞는 반려견을 AI가 1위부터 5위까지 추천해 드립니다" | Play 스토어 설명 | 확인 |

**추정**: 사람이 답하는 10문항은 개의 성향 10축과 1:1로 대응하는 "희망 수치"다. 근거는 (a) 자사 문구가 "나의 희망 수치와 아이의 성향을 한눈에 비교"라고 직접 말하고, (b) 개 쪽 축이 정확히 10개이며, (c) 문항 수도 10개로 같고, (d) 결과가 두 벡터의 유사도로 보이는 백분율(100%/71%/68%/53%)이기 때문이다.

**미확인**: 실제 문항 텍스트. App Store·Play 스크린샷 12장 전체를 확인했으나 설문 화면 스크린샷이 없고, 웹의 `/matching` 경로는 404다. 앱 설치 없이는 문항 원문 확보 불가.

**미확인 (중요)**: 주거 형태, 집 크기 제한(kg 상한), 임대인 동의, 평일에 집이 비는 시간, 동거 가족 구성, 양육 경험, 첫 달 기대치를 묻는다는 근거를 **어디에서도 찾지 못했다**. Play 설명의 "나의 거주 환경"이 유일한 관련 표현인데, 개 쪽 10축에 주거를 받을 자리가 없어서 실제 반영 여부가 불투명하다. 반대로 "동거 가족 중 아이·다른 개·소동물"은 개 쪽 축(어린이·다른개·소동물)의 거울 문항으로 존재할 가능성이 높다. (추정)

### 3-4. 매칭 결과 화면 (확인, App Store 스크린샷)

- 제목 "🧬 AI 매칭 결과", 우상단 [공유] [닫기]
- 1위~4위(설명상 5위까지) 랭킹 카드. 각 카드에 **"100% 찰떡!" "71% 찰떡!" "68% 찰떡!" "53% 찰떡!"** 백분율 + 이름 + 품종 + 성별/중성화/나이 배지
- **추천 이유 문장 없음.** 왜 71%인지, 어떤 축이 맞고 어떤 축이 어긋나는지 결과 목록에서는 알 수 없다
- 개별 개 상세로 들어가야 "📊 바른매칭 성향 분석 리포트" 막대 10개를 볼 수 있고, 이것도 개의 절대 수치일 뿐 사람 답변과의 대조 표시는 스크린샷에서 확인되지 않는다
- 결과는 "예쁜 프리미엄 이미지 카드"로 공유 가능 (App Store 설명, 확인)

### 3-5. 보호소 채팅 (확인)

앱 내 1:1 채팅. 화면 상단에 "하양 (문의자: 카카카오)" 형식으로 개 이름과 문의자가 표시되고, 개 상세의 [입양 문의하기] 버튼에서 시작된다. 웹에서는 채팅이 제공되지 않고 "안전하고 투명한 프리미엄 입양 문화를 위해 바른매칭 전용 앱에서 자동 본인인증 후 1:1 채팅을 이용해 주세요"라고 앱으로 유도한다. (https://www.barunmatch.com/44)

### 4-2. 사설보호소 데이터

- **Firebase**(프로젝트 `barunmatch-f6a72`) Firestore `dogs` 컬렉션 + Firebase Storage. (확인, /43 페이지 소스)

### 4-3. 성향 데이터를 누가 넣는가

**보호소 담당자 또는 운영자(master)가 슬라이더로 직접 입력한다.** (확인, /375188206 등록 폼 코드)

추가로 발견한 사실 하나. 웹 등록 폼의 저장 로직 `saveDogData()`에서 Firestore에 쓰는 `dogData` 객체에 **성향 10개 값이 빠져 있다**. 코드에 `// ... 성향 데이터parseInt 추가`라는 미완성 주석만 남아 있다. (확인, /375188206 페이지 소스)

```js
const dogData = {
  "이름": ..., "이미지주소": ..., "나이": ..., "체중": ...,
  "크기": ..., "보호소": ..., "updatedAt": new Date()
  // ... 성향 데이터parseInt 추가
};
```

즉 **웹 경로로 등록된 개는 성향 값이 저장되지 않고, 조회 시 전 축 기본값 5점으로 표시된다.** 앱 내 등록 경로도 같은지는 미확인. 발표에서 쓸 때는 "공개된 웹 등록 폼 기준"이라고 범위를 밝힐 것.

### 4-4. 매칭 알고리즘

**미확인.** "AI"라고 표기하지만 LLM이나 학습 모델을 쓴다는 근거는 없다. 사람의 희망 수치 10개와 개의 성향 수치 10개를 비교해 백분율을 내는 **규칙 기반 유사도 계산**으로 추정한다. 근거는 자사 문구가 "한눈에 비교"라고 표현하고, 개 쪽 데이터가 0~10 정수 10개뿐이라 그 이상의 입력이 없기 때문이다. (추정)

## 8. 발표 방어 포인트 3개

심사위원이 "바른매칭이랑 뭐가 다르냐"고 물으면 이 순서로 답한다. 셋 다 확인된 사실만 쓴다.

### 방어 1. 바른매칭은 "어떤 개를 원하냐"를 묻고, 이름표는 "당신 집에서 뭐가 불가능하냐"를 묻는다

바른매칭의 매칭 축은 개의 성향 10종이고(신체운동·두뇌자극·실내차분·분리불안·경계짖음·요구짖음·낯선사람·어린이·다른개·소동물), 사람에게 받는 것은 그 축의 **희망 수치**입니다. 자사 홈페이지 문구 그대로 "나의 희망 수치와 아이의 성향을 한눈에 비교"입니다.

그런데 국내외 연구에서 개 파양 사유 1위는 **주거 문제**이고(Salman 1998, 29.1%), 그 안에서 가장 큰 하위 유형이 **품종·크기 제한**입니다(Applebaum 2024, 27%). 바른매칭의 10축에는 주거를 받을 자리가 아예 없습니다. 임대인 동의, 관리규약 kg 상한, 평일에 집이 비는 시간 중 어느 것도 묻는다는 근거를 공개 자료 어디에서도 찾지 못했습니다.

이름표는 이 셋을 **하드 필터**로 둡니다. 25kg 제한 단지에 30kg 개를 추천하지 않고, 임대인이 반대한 경우에는 결과 대신 동의를 받는 방법을 보여줍니다. 취향 매칭이 아니라 **파양 예측 변수 매칭**입니다.

*(반박 대비: Play 스토어 설명에는 "나의 거주 환경"이라는 표현이 한 번 나옵니다. 다만 개 쪽 10축에 대응 항목이 없어 실제 반영 여부는 확인되지 않습니다. 이 점은 "확인 못 했다"고 정직하게 말할 것.)*

### 방어 2. 바른매칭의 성향 데이터는 보호소가 손으로 채워야 하고, 공고 데이터 수천 건에는 그 데이터가 없다

바른매칭의 성향 10종은 AI가 추정하는 게 아니라 **보호소 담당자가 0~10 슬라이더로 직접 입력**합니다. 운영 코드에서 확인했습니다. 값이 비면 전 축이 기본값 5점으로 표시됩니다.

문제는 모집단입니다. 앱이 보여주는 지자체 공고는 시보호소 2,041마리, 공고중 1,314마리 규모인데, 공고 데이터에는 성향 필드 자체가 없습니다. 성향이 있는 건 **자체 DB에 등록된 파트너 사설보호소의 소수 개체**뿐입니다. 실제 매칭 결과 화면에도 4마리가 나옵니다. 게다가 공개된 웹 등록 폼은 성향 값을 저장조차 하지 않은 채 배포돼 있고, 코드에 미완성 주석이 남아 있습니다.

이름표는 반대로 **공고 데이터에 이미 있는 필드**(체중, 품종, 특징란, 중성화, 공고 마감일)에서 파생 변수를 뽑아 규칙으로 점수를 냅니다. 보호소가 새로 입력해 줘야 작동하는 구조가 아니라서 **첫날부터 전국 공고 전체에 적용**됩니다.

### 방어 3. 바른매칭의 사업 실체는 매칭이 아니라 198,000원 용품 판매이고, 그래서 결과에 근거 문장이 없다

바른매칭 홈페이지 푸터에 이렇게 적혀 있습니다. "바른매칭은 반려동물 용품 및 콘텐츠를 판매하는 통신판매업체입니다. 동물을 직접 판매하거나 소유권을 이전하지 않으며, 입양 계약의 법적 책임은 보호소와 입양 당사자에게 있습니다." 웹사이트 대부분은 하이엔드 용품 큐레이션이고, "검증시스템" 페이지의 검증은 입양 환경이 아니라 **용품 품질 검수 5단계**입니다.

그 결과가 화면에 드러납니다. 매칭 결과는 "100% 찰떡", "71% 찰떡" 같은 **백분율 배지와 공유용 카드**일 뿐, 왜 그 점수인지 설명하는 문장이 없습니다. 입양 후 체크리스트나 교육도 없고, 그 자리를 198,000원 스타터 키트가 채웁니다.

이름표는 점수를 숨기고 **"잘 맞는 이유 2문장"**을 보여줍니다. 그 문장은 LLM이 자유롭게 쓰는 게 아니라 **적용된 규칙 목록 안에서만** 생성되고, 규칙과 어긋나면 검증 실패로 처리합니다. 그리고 카드마다 **보호소에 물어볼 질문**을 자동으로 만들어 사람의 검토를 한 번 강제합니다. 우리는 매칭 자체가 제품이라 근거를 설명할 이유가 있고, 바른매칭은 매칭이 유입 장치라 설명할 이유가 없습니다.

**숫자로 마무리할 때**: 바른매칭은 2026년 4월 18일에 나온 개인사업자 앱으로 Play 다운로드 500+, App Store 평가 2건이고, 2026년 5월 5일 이후 업데이트가 없습니다. 시장을 선점당한 상황이 아닙니다.

## 9. 미확인 목록

발표 중 질문이 나올 수 있는 항목들이다. **모르면 모른다고 답할 것.**

1. **입양 희망자 10문항의 실제 문항 텍스트.** 앱 설치가 필요하다. 스토어 스크린샷 12장에 설문 화면이 없고, 웹 `/matching`은 404.
2. **주거 형태·크기 제한·임대인 동의·집 비는 시간을 정말 안 묻는가.** "묻는다는 근거를 못 찾았다"까지만 확인됐다. 안 묻는다고 단정하면 위험하다.
3. **매칭 알고리즘의 실체.** 규칙 기반 유사도로 추정하지만 미확인. LLM 사용 여부도 미확인.
4. **지자체 공고 데이터의 실제 취득 경로.** 공고번호 형식은 국가동물보호정보시스템과 일치하나, 공공데이터포털 API 직접 호출인지 크롤링인지 Airtable 수작업인지 앱 쪽은 확인 못 했다. 웹 쪽만 Airtable로 확인됨.
5. **앱 내 개 등록 경로에서도 성향 값이 누락되는가.** 웹 폼에서만 확인됨.
6. **파트너 사설보호소의 실제 수와 등록 개체 수.** 스크린샷에서 개체명 5~6개만 확인.
7. **입양 성사 건수, MAU, 재방문율.** 일체 미공개.
8. **매출.** 스타터 키트 판매 실적 미공개.
9. **법인 등기 여부와 팀 규모.** 개인사업자로 보이나 등기 미조회. 앱 개발이 외주인지 자체인지도 미확인.
10. **언론 보도·수상·지원사업의 진짜 부재 여부.** 검색 범위 내 부재일 뿐이다.
11. **Android 앱의 실제 리뷰 내용.** Play 리뷰 본문 미확보.
12. **"이리와", "펫버디"의 조건 입력 매칭 기능 유무.** 시간상 미조사.
