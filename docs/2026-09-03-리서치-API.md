# 구조동물 조회 서비스 API 조사 (2026-09-03 기준)

조사 방법: data.go.kr 상세페이지에 **임베드된 공식 Swagger 스펙 JSON을 통째로 추출**해 필드/파라미터를 확정했고,
값 형식은 (a) 국가동물보호정보시스템(animal.go.kr) 실데이터 13건 직접 조회 + (b) GitHub에 공개된 실제 API 응답 54건 덤프로 교차검증했다.
"미확인"으로 표시된 항목은 근거를 찾지 못한 것이다.

### 구버전 폐기 여부 (실측)

`serviceKey=test`로 각 경로를 직접 호출해 게이트웨이 응답으로 판정했다.
`NO_OPENAPI_SERVICE_ERROR`(코드 12) = "해당 오픈API 서비스가 없거나 폐기됨", `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`(코드 30) = 서비스는 살아있고 키만 무효.

| 경로 | 응답 | 판정 |
|---|---|---|
| `/1543061/abandonmentPublicService_v2/abandonmentPublic_v2` | 코드 30 | **살아있음** |
| `/1543061/abandonmentPublicService_v2/{sido_v2,sigungu_v2,shelter_v2,kind_v2}` | 코드 30 | **살아있음** (4개 전부) |
| `/1543061/abandonmentPublicSrvc/abandonmentPublic` (구버전) | 코드 12 | **폐기됨** |
| `/1543061/abandonmentPublicSrvc/{sido,sigungu,shelter,kind}` | 코드 12 | **폐기됨** |
| `/1543061/abandonmentPublicSrvc_v2/...` | 코드 12 | 존재하지 않음 (경로명 주의) |

**서비스명은 `abandonmentPublicSrvc_v2`가 아니라 `abandonmentPublicService_v2`다.** (`Srvc`가 아니라 `Service`)

레거시 호스트 `http://openapi.animal.go.kr/openapi/service/rest/abandonmentPublicSrvc/abandonmentPublic`는 아직 응답하지만
`UNREGISTERED IP ERROR`(코드 32)를 반환한다. IP 등록 기반 별도 채널이며 신규 사용 대상이 아니다.

Swagger의 각 오퍼레이션 `description`도 이관을 명시한다:
> "End Point 뒤에 abandonmentPublic_v2를 붙여서 실행해야 합니다.(http://apis.data.go.kr/1543061/abandonmentPublicService_v2/abandonmentPublic_v2)"

**v1 → v2 변경 내역 공식 공지는 미확인.** 다만 스펙 비교로 확인된 차이:
- **추가**: `sfeSoci`(사회성), `sfeHealth`(건강), `etcBigo`(특이사항), `kindFullNm`, `upKindCd`, `upKindNm`, `kindNm`, `popfile3~8`, `vaccinationChk`, `healthChk`, 입양/봉사/행사 안내 블록(`adptn*`, `sprt*`, `srvc*`, `evnt*`)
- **추가 요청 파라미터**: `bgupd`/`enupd`(수정일 범위), `sex_cd`, `rfid_cd`, `desertion_no`, `notice_no`
- **삭제**: `chargeNm`(담당자), `officetel`(담당자 연락처): v2 응답 스펙에 없음 (Swagger 전체 grep 결과 0건)

## 2. 엔드포인트 & 요청 파라미터

전부 `GET`. 공통: `serviceKey`(필수, URL 인코딩된 Encoding 키), `_type`(`xml` 기본 / `json`), `numOfRows`(≤1000, 기본 10), `pageNo`(기본 1).

### 2-1. `/abandonmentPublic_v2`: 구조동물 조회 (메인)

| 파라미터 | 필수 | 의미 |
|---|---|---|
| `serviceKey` | O | 공공데이터포털 발급 인증키 |
| `bgnde` | X | 구조날짜 검색 시작일 (YYYYMMDD) |
| `endde` | X | 구조날짜 검색 종료일 (YYYYMMDD) |
| `upkind` | X | 축종코드 (개 417000 / 고양이 422400 / 기타 429900) |
| `kind` | X | 품종코드 (`kind_v2`로 조회) |
| `upr_cd` | X | 시도코드 (`sido_v2`로 조회) |
| `org_cd` | X | 시군구코드 (`sigungu_v2`로 조회) |
| `care_reg_no` | X | 보호소번호 (`shelter_v2`로 조회) |
| `state` | X | 전체: 빈값 / 공고중: `notice` / 보호중: `protect` |
| `neuter_yn` | X | 전체: 빈값 / `Y` / `N` / `U` |
| `sex_cd` | X | 전체: 빈값 / `M` / `F` / `Q` |
| `bgupd` | X | 수정날짜 검색 시작일 (YYYYMMDD) |
| `enupd` | X | 수정날짜 검색 종료일 (YYYYMMDD) |
| `rfid_cd` | X | 동물등록번호(RFID) |
| `desertion_no` | X | 유기번호 |
| `notice_no` | X | 공고번호 |
| `pageNo` / `numOfRows` / `_type` | X | 공통 |

> `state` 요청값은 소문자 영문(`notice`/`protect`)인데 응답 `processState`는 한글(`공고중`/`보호중`)이다. 서로 다른 어휘다.

### 2-2. 보조 엔드포인트

| 엔드포인트 | 필수 파라미터 | 응답 필드 |
|---|---|---|
| `/sido_v2` (시도 조회) | 없음 | `orgCd`(시도코드), `orgdownNm`(시도명) |
| `/sigungu_v2` (시군구 조회) | `upr_cd` | `orgCd`(시군구코드), `orgdownNm`(시군구명), `uprCd`(상위코드) |
| `/shelter_v2` (보호소 조회) | `upr_cd`, `org_cd` | `careNm`(보호소명), `careRegNo`(보호소번호) |
| `/kind_v2` (품종 조회) | `up_kind_cd` | `kindNm`(품종명), `kindCd`(품종코드) |

> `shelter_v2`는 `upr_cd`와 `org_cd`가 **둘 다 필수**다. 전국 보호소를 한 번에 못 받는다.
> `kind_v2`의 파라미터는 `up_kind_cd`(언더스코어 있음)인데 메인 조회는 `upkind`(언더스코어 없음)다. **이름이 다르다.**

### 2-3. 공통 응답 봉투

```
response.header.{reqNo, resultCode, resultMsg, errorMsg}
response.body.{numOfRows, pageNo, totalCount}
response.body.items.item[]   ← 배열
```

## 6. 응답 형식 / CORS / 인코딩

| 항목 | 결과 | 근거 |
|---|---|---|
| JSON 지원 | **O**: `_type=json` (기본값은 `xml`) | Swagger 파라미터 |
| HTTPS | **O**: `https://apis.data.go.kr/...` 정상 | 직접 호출 확인 |
| CORS (단순 요청) | **O**: `Access-Control-Allow-Origin`이 요청 `Origin`을 그대로 에코 | 직접 호출 확인 |
| CORS (프리플라이트) | **O**: `OPTIONS` → `200`, `Access-Control-Allow-Methods: GET,OPTIONS`, `Access-Control-Max-Age: 3600` | 직접 호출 확인 |
| 이미지 HTTPS | **O**: `https://openapi.animal.go.kr/...` 도 `200` | 직접 호출 확인 |

실측 로그:
```
$ curl -X OPTIONS -H 'Origin: https://foo.dev' -H 'Access-Control-Request-Method: GET' \
    https://apis.data.go.kr/1543061/abandonmentPublicService_v2/abandonmentPublic_v2
HTTP/1.1 200 OK
Access-Control-Allow-Origin: https://foo.dev
Access-Control-Allow-Methods: GET,OPTIONS
Access-Control-Max-Age: 3600
```

**결론: 서버 프록시 없이 브라우저에서 직접 fetch 가능하다.** 워크숍에선 정적 페이지 하나로 끝낼 수 있다.

주의 2가지:
1. **serviceKey가 클라이언트에 노출된다.** 워크숍 데모면 감수 가능하지만, 공개 배포하면 남이 쓴다(일 10,000건 공유). 실서비스면 프록시 필요.
   프록시 예제: [uzchang91/PumON `proxy.cjs`](https://github.com/uzchang91/PumON/blob/main/proxy.cjs)
2. **이미지 URL은 `http://`로 온다.** HTTPS 페이지에 그대로 넣으면 mixed content로 차단된다.
   → `popfile1.replace(/^http:/, 'https:')` 로 치환. HTTPS로도 `200` 나오는 걸 확인했다.
   단 응답 헤더가 `Content-Type: application/octet-stream` + `Content-Disposition: attachment`이므로
   `<img>` 렌더링은 워크숍 전에 **한 번 눈으로 확인**할 것 (`X-Content-Type-Options: nosniff`는 없어서 통상 렌더된다).

## 9. 매칭 규칙 설계 시 주의점

근거 있는 것만 적는다.

### 9-1. `weight`는 반드시 파싱해야 하고, **콤마 소수점이 실존한다**

관측된 형태: `"11(Kg)"`, `"2.8(Kg)"`, `"1.00(Kg)"`, `"5.22(Kg)"`, **`"0,25(Kg)"`, `"0,26(Kg)"`**.
animal.go.kr 실조회 10건 중 **3건이 콤마 소수점**이었다(인제군동물보호센터). 보호소별 입력 습관 차이로 보인다.
`parseFloat("0,25")` → `0` 이 되므로 **소형견이 0kg으로 둔갑한다.** 활동량/주거 매칭이 조용히 망가지는 지점이다.

```js
const kg = (w) => {
  const m = String(w ?? '').replace(/\s/g, '').match(/^([\d.,]+)\(?Kg\)?/i);
  if (!m) return null;
  const n = parseFloat(m[1].replace(',', '.'));   // 콤마 → 점
  return Number.isFinite(n) && n > 0 ? n : null;  // 0/결측은 null로
};
```
`"  3,50 (Kg)"` 같은 공백 포함 케이스도 실제 파서 테스트에 있으니 공백 제거 먼저.

### 9-2. `age`는 `YYYY(년생)` 외에 **`YYYY(60일미만)(년생)` 변형이 24%**

54건 중 13건(24%)이 `"2025(60일미만)(년생)"` 형태였고, 실조회 10건 중 7건이 그랬다.
`age.split("(년생)")[0]` 같은 흔한 처리는 `"2025(60일미만)"`을 뱉는다.

```js
const birthYear = (a) => { const m = String(a ?? '').match(/^(\d{4})/); return m ? +m[1] : null; };
const isNeonate = (a) => /60일미만/.test(String(a ?? ''));
```
그리고 **`age`는 나이가 아니라 출생연도다.** `2026 - birthYear`도 만 나이가 아니라 최대 1년 오차가 있는 근사치다.
"1살 이하 강아지" 같은 규칙을 쓸 거면 오차를 감안하거나 `60일미만` 플래그를 따로 쓰는 게 낫다.

### 9-3. 품종 기반 규칙은 약하다: 믹스가 85%

표본 기준 개의 85.7%가 `믹스견`, 고양이의 86.4%가 `한국 고양이`다.
"푸들은 실내 적합, 진돗개는 마당 필요" 같은 견종 지식 규칙을 만들면 **전체의 15%에게만 적용되고 나머지는 전부 기본값으로 떨어진다.**
→ **주거 형태·활동량 매칭은 `kindNm`이 아니라 `weight`를 1차 축으로 삼을 것.** 체중은 결측이 거의 없고 연속값이라 규칙 만들기도 쉽다.
품종은 "선호 품종이 있으면 가산점" 정도의 보조 축으로.

### 9-4. `sfeSoci`/`sfeHealth`/`etcBigo`에 의존하지 말 것

이름만 보면 성격 매칭에 딱인 필드지만, **실측 13건 전부 비어 있었고 54건 덤프에는 키 자체가 없었다.**
사회성 신호는 전부 **`specialMark` 자유 텍스트**에 들어있다.
실제 값: `"사람경계 없음"`, `"겁이많고 사람을 견제함"`, `"진드기많음,사람좋아함"`, `"작고 소중한 아이, 생후3주령 추정, 눈곱 있음"`.
→ 성격/양육난이도 축은 `specialMark` **키워드 매칭**으로 짜야 한다. 예: `사람좋아함|친근|순함|애교` → 사회성 高 / `겁많|예민|경계|공격` → 경험자 권장 / `부상|절단|구내염|영양상태불량|기력없음` → 의료 부담 高.
어디까지나 휴리스틱이고 결측도 많다는 걸 UI에 반영할 것.

### 9-5. 지역 매칭은 `orgNm` 또는 `careAddr`로: 응답에 지역 코드가 없다

응답 `item`에 `orgCd`/`uprCd`가 **없다.** `orgNm`(`"경기도 안산시"`)과 `careAddr`(전체 주소) 문자열뿐이다.
지역 필터는 **요청 시 `upr_cd`/`org_cd`로 거는 게 정석**이고, 응답을 사후 필터링하려면 `orgNm` 앞 2토큰을 쓰는 수밖에 없다.
그리고 시도 목록에 **`전남광주통합특별시`(6130000)** 가 있고 광주광역시·전라남도가 없다. 드롭다운 하드코딩하면 여기서 깨진다.
`happenPlace`(발견장소)는 `"장안면 상두원길 인근"`처럼 시도가 빠진 자유 텍스트라 지역 매칭에 쓰면 안 된다.

### 9-6. `neuterYn`을 필터로 쓰면 후보가 급감한다

표본 분포: `N` 39 / `U` 12 / `Y` 3. **중성화 완료(`Y`)는 5.6%뿐이고 미상(`U`)이 22%다.**
"중성화된 아이만" 필터를 하드 필터로 걸면 결과가 거의 안 나온다. 가산점 축으로 쓰거나, `U`를 배제하지 말 것.
`sexCd`도 `Q`(미상)가 9% 있다.

### 9-7. `colorCd`는 규칙에 쓸 수 없다

54건 중 28종. 구분자가 `&`, `/`, 없음이 뒤섞이고(`"갈색&검정"`, `"흰색/검은색 얼룩무늬"`, `"검은색흰색황토색조합"`),
`"기타(흰갈)"` 같은 괄호 표기와 `"평행·전체·부분줄무늬"` 처럼 색이 아닌 값까지 들어온다.
표시용으로만.

### 9-8. `noticeSdt == noticeEdt` 인 레코드가 있다

표본에 `noticeSdt: "20250920"`, `noticeEdt: "20250920"`인 건이 있었다. 공고기간을 `edt - sdt`로 계산해 "남은 일수"를 보여주면 0 또는 음수가 나온다.
마감 임박 정렬을 쓸 거면 방어 필요. (정상 케이스는 `20260903 ~ 20260914`처럼 10일 내외)

### 9-9. 상태 필터: `state` 요청값과 `processState` 응답값의 어휘가 다르다

요청은 `notice`/`protect`(영문), 응답은 `공고중`/`보호중`/`종료(...)`(한글).
입양 매칭이면 `state=protect`(입양대상, 실측 2,362건)가 `notice`(공고중, 소유자 반환 대기 기간)보다 목적에 맞다.
`state`를 비우면 `종료(안락사)` 같은 개체까지 섞여 들어오므로 **반드시 지정할 것.**

### 9-10. 이미지는 1·2번만 신뢰

`popfile1`/`popfile2`는 54/54 존재하지만 `popfile3`은 3/54, `popfile5~8`은 1건 이하다. 갤러리 UI를 3장 이상 전제로 짜면 대부분 빈칸이 된다.

### 9-11. 전량 수집이 페이지네이션보다 낫다

전국 공고가 2,400~2,600건이고 `numOfRows` 상한이 1,000이므로 **3회 호출로 전량 확보**된다.
개발계정 일 10,000건 한도에 견줘 여유가 크다. 워크숍에선 서버 필터 조합을 실험하느라 시간 쓰지 말고,
`state=protect`만 걸어 전량 받아서 클라이언트에서 규칙을 돌리는 편이 반복 속도가 훨씬 빠르다.
